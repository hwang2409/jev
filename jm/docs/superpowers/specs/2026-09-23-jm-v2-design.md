# jm v2 design spec

**Status:** proposal for review
**Date:** 2026-09-23
**Owner:** Henry
**Scope:** design only; this document does not implement jm v2

## 1. decision summary

jm v2 keeps the v1 finite-state runner, cache, JSONL records, presets, and gate
policy language. It adds four features in this order:

1. jm owns the only Jev client in this repository.
2. `jm calibrate` replays cached cases against the live model.
3. An opt-in local lexical prefilter reduces state visits while reporting its
   recall boundary.
4. `--consistency N` repeats Noul judgments with fresh throwaway state IDs.

The v2 design extends `runner`, `answers`, `cache`, `gates`, and `presets`. It
does not add a second judgment engine. It does not support the native TypeSafe
endpoint. The Vercel AI Gateway is the only transport.

The economic unit remains one state visit. A question battery travels with one
state. Questions are cheap compared with visiting another state, so the
runner keeps batteries dense and state admission explicit.

### 2.1 Gateway transport

Every jm call uses:

- `POST https://ai-gateway.vercel.sh/v4/ai/evaluation-model`.
- No model field in the request body.
- `Content-Type: application/json` and `Accept-Encoding: identity`.
- These four Gateway protocol headers: `ai-evaluation-model-specification-version: 4`,
  `ai-gateway-auth-method: api-key`, `ai-gateway-protocol-version: 0.0.1`,
  and `ai-model-id: typesafe-ai/jev`.
- `providerOptions.gateway.zeroDataRetention: true`.
- A bearer key resolved in this order: `VERCEL_AI_GATEWAY`,
  `AI_GATEWAY_API_KEY`, `VERCEL_JEV_KEY`, then matching assignments in
  `~/.zshrc`.

The body contains `state` and `questions`. A Noul question is sent as
`type: boolean`. Gateway boolean answers are normalized back to the public
`type: noul` and `noul: <probability>` shape.

Gateway Choice and Score answers may omit the native `confidence` and
`legend` fields. jm rebuilds those fields from the requested battery.

The client retries HTTP 429 and 529 only. It uses the retry policy in
`jm/jm/api.py` as the source of truth. A finite, non-negative `Retry-After`
hint is honored as given, including a 59-second hint. The client does not add
a 60-second minimum. Only an absurd hint is bounded by the configured maximum
wait. Missing or invalid hints use bounded exponential backoff. The client
never retries a 4xx validation or auth error. The default attempt budget stays
three attempts. The free-tier operating limit is 30 requests and 250,000
tokens per minute per model. The client does not pretend that token cost can
be known before a response.

The client never logs, returns, caches, or includes the Gateway key in an
error. The native `JEV_API_KEY` path is deleted from the v2 design.

### 2.2 normalized answers

`jm.client` is the normalization boundary. Callers see one stable response
shape regardless of Gateway omissions:

```json
{
  "answers": {
    "is_match": {"type": "noul", "noul": 0.82},
    "kind": {
      "type": "choice",
      "choice": "billing",
      "probabilities": {"billing": 0.8, "technical": 0.2},
      "confidence": 0.6
    },
    "risk": {
      "type": "score",
      "score": 1.7,
      "legend": {"0": "low", "1": "medium", "2": "high"},
      "probabilities": {"0": 0.1, "1": 0.1, "2": 0.8},
      "confidence": 0.7
    }
  },
  "usage": {"input_tokens": 120, "output_tokens": 20},
  "served_model": "jev-1.13.0"
}
```

The exact public rules are:

- Noul has only `type` and `noul`. It has no confidence field. A caller that
  needs an uncertainty band uses the raw probability: below `0.30` is a
  strong no, above `0.70` is a strong yes, and the inclusive middle band is
  uncertain.
- Choice has `choice` and the full `probabilities` map. If Gateway omits
  confidence, jm derives it as `(count * largest_p - 1) / (count - 1)`, where
  `count` is the number of options in the requested question, not the number
  of keys returned in the probability map.
- Score has a probability-weighted `score`, the full probability map, and a
  legend. If Gateway omits confidence, jm uses the same distribution formula
  with the full criteria count from the requested question. If Gateway omits
  the legend, jm rebuilds level-string keys from the original ordered score
  criteria. Structured criteria values remain structured; jm does not invent a
  prose description.
- Unknown answer IDs, wrong answer types, missing required fields, non-finite
  numbers, and malformed probability maps are errors. jm does not silently
  accept an answer from a different primitive.
- `usage` maps Gateway camelCase keys to snake_case. At minimum this includes
  `inputTokens` to `input_tokens` and `outputTokens` to `output_tokens`.
  Future known token fields use the same mapping. Unknown fields remain in the
  usage object so usage data is not lost.
- `served_model` comes from Gateway provider metadata when available. The
  configured model remains the stable ID `typesafe-ai/jev`.

The normalized shape is shared by the CLI runner and all three external
callers. The CLI may add its existing record metadata, cache metadata, and
consistency details around this shape.

### 2.3 public library surface

The working public module is `jm.client`. It exposes only the following
concepts:

```python
from jm.client import JevClient, JevError, JevResponse

client = JevClient()
response = client.evaluate(state, questions)
```

The async caller uses the matching async method on the same client contract:

```python
response = await client.evaluate_async(state, questions)
```

The exact implementation may use one shared transport core with sync and
async adapters. It must not expose `httpx`, Gateway headers, key lookup,
retry helpers, or wire-specific answer parsing to callers.

`JevResponse` contains normalized `answers`, normalized `usage`, and optional
`served_model` and latency metadata. `JevError` contains a safe message,
optional HTTP status, and attempt count. It never contains credentials or
unbounded response text.

The library does not own jm's content-addressed cache. `runner` owns cache
lookup and publication because cache keys include preset, chunking, limits,
question battery, and state. The library receives one already-resolved state
and battery per call.

### 3.3 packaging recommendation

Use a relative uv path dependency. Keep `jm`, `harness`, `router`, and `laya`
as separate runnable projects. Add `jm` as a normal dependency and configure
the local source in each consumer project:

```toml
[project]
dependencies = ["jm"]

[tool.uv.sources]
jm = { path = "../jm", editable = true }
```

The exact relative path depends on the consumer directory. This avoids
absolute paths, `PYTHONPATH` edits, vendored copies, and a new repository-wide
lockfile. It also lets a consumer keep its current environment and lets jm
remain independently installable through its existing `jm` console script.
The migration tasks add the smallest missing project metadata to router or
laya if their current script layout needs it.

Do not make callers shell out to `jm`. A subprocess would lose typed errors,
async reuse, and the one-client boundary. Do not copy jm source into a caller.

## 4. `jm calibrate`

### 4.1 purpose

Thresholds do not transfer safely across Jev model versions, Gateway routing
changes, or altered question batteries. `jm calibrate` makes every model bump
produce a comparable, reviewable report before a preset or gate is updated.

The command replays complete cached cases against the live Gateway. The cached
answer is the baseline. The live answer is the candidate. Calibration never
uses the cache for the candidate call and never overwrites the baseline.

The PR #34 spot-check is the prototype pattern: 30 recorded cases, zero
choice flips, and a maximum delta of 0.02. It is evidence for the report
shape, not a permanent acceptance threshold.

### 4.2 command and inputs

The initial command is:

```text
jm calibrate --preset NAME [--cache-dir PATH]
              [--threshold-margin FLOAT]
              [--max-choice-flips N]
              [--max-probability-delta FLOAT]
              [--max-score-delta FLOAT]
              [--max-noul-delta FLOAT]
              [--repeats N]
              [--max-threshold-crossings N]
              [--format jsonl]
```

The command reads complete cache entries for the selected preset. It rejects
partial, malformed, or mixed-preset entries before making live calls. It
accepts v1 cache entries as read-only input so the first v2 calibration can
measure the existing dataset. New cache writes use the v2 cache schema.

Calibration defaults are versioned as `jm.calibration/v1`. Unless a preset or
command flag overrides them, the defaults are `threshold_margin=0.05`,
`max_choice_flips=0`, `max_probability_delta=0.05`, `max_score_delta=0.50`,
`max_noul_delta=0.05`, `max_threshold_crossings=0`, and `repeats=1`.
`max_choice_flips` and `max_threshold_crossings` count cases. The other max
values are absolute numeric deltas. A future preset may pin these values in a
versioned `calibration` section, but a command flag always wins. The first
implementation must not hide tolerance values in code.

`--repeats N` defaults to `1` and must be positive. Values above one repeat
each candidate case with a fresh throwaway `uid` in the state context. The
stable cache key and `state_ref` remain tied to the original case. Calibration
uses the same repeat-sampling contract that the later `--consistency` feature
must reuse; it does not invent a second meaning for a fresh uid.

The candidate uses the current Gateway alias and records the served model when
Gateway provides it. The report includes both the cached model metadata and
the candidate served model. A missing served-model value is reported as
`unknown`, not guessed from the alias.

Every case preserves its baseline and candidate `served_model` value. The
summary also records served-model counts separately for each side, counting
`unknown` as a value. A comparison is mixed when either side has more than one
distinct value, including `unknown`. Mixed comparisons emit their case
records and summary, set `within_tolerance` to `null`, and exit `2`; they do
not pass or fail model drift. A single baseline model and a different single
candidate model are a valid comparison.

### 4.3 comparison rules

Each case emits one JSONL case record. It includes the stable cache key, state
reference, question ID, primitive, baseline answer, candidate answer, and
usage for the candidate call. It reports:

- `choice_flip`: true when the selected Choice changes.
- `probability_delta`: maximum absolute probability change over the union of
  option or level keys.
- `score_delta`: absolute Score change.
- `noul_delta`: absolute Noul probability change.
- `gate_values`: the mapped values consumed by gates: Choice `choice`, Score
  `score`, and Noul `noul`.
- `derived_confidence`: the baseline and candidate Choice or Score confidence.
  When Gateway omits confidence, calculate it as
  `(criteria_count * largest_probability - 1) / (criteria_count - 1)`.
  `criteria_count` comes from the question's options or criteria. Never derive
  it from a sparse returned probability map. For one criterion, confidence is
  `1.0`.
- `thresholds`: every supported preset threshold for that question, with its
  exact gated field, operator, target, baseline value, candidate value,
  distance, near-threshold flag, and crossing flag. Supported fields are the
  numeric Score value and Noul probability fields already accepted by the
  preset schema.

Calibration compares the exact supported field consumed by the gate. Choice
identity and derived confidence remain diagnostic through `choice_flip` and
`derived_confidence`; they cannot be preset threshold fields in v2. Raw
probability maps are diagnostic except for their aggregate
`probability_delta` metric.

For numeric fields, distance is the absolute distance to the configured bound,
and `near_threshold` means that distance is at most
`--threshold-margin`. A crossing means that baseline and candidate are on
opposite sides of the bound. The report never treats a Score as a precise
magnitude beyond the preset's numeric gate comparison.

When `--repeats` is greater than one, classify each changed case before
counting drift. A discrete Choice is `stable_drift` when every candidate
repeat has the same changed identity. A continuous Score or Noul value is
`stable_drift` when every repeat exceeds its field tolerance from baseline,
all repeats have the same signed direction, all applicable repeats have the
same threshold side, and the candidate range is no larger than that field's
tolerance. If no threshold exists, the threshold-side condition is empty.
Repeats that disagree, change signed direction, straddle a threshold, or
exceed the numeric spread bound are `boundary_noise`. Boundary noise is
indeterminate and is never counted as stable drift. The summary reports both
counts.

A qualifying run passes only when choice flips are at most
`max_choice_flips`, observed probability, Score, and Noul deltas are at most
their matching defaults or overrides, threshold crossings are at most
`max_threshold_crossings`, and stable drift is zero. Boundary noise prevents
a decision. These rules apply even when a preset has no thresholds.

If no cases qualify for comparison, report
`no qualifying cases`, set the comparison count to zero, and do not emit a
passing `0.0000` delta. The summary must set `within_tolerance` to `null` and
the command exits `2` because it has no evidence for a calibration decision.

The command emits a final JSONL summary record with counts, maxima, model
metadata, `baseline_model_counts`, `candidate_model_counts`, tolerance values,
and `within_tolerance`. Human summary text goes to stderr so stdout remains
machine-readable JSONL.

The summary ends with a pasteable provenance line:

```text
# jm calibrate 2026-09-23: preset=jgrep preset_version=1 cases=30 repeats=1 baseline=jev-1.13.0 candidate=jev-1.14.0 baseline_models=jev-1.13.0:30 candidate_models=jev-1.14.0:30 tol_threshold_margin=0.0500 tol_max_choice_flips=0 tol_max_probability_delta=0.0500 tol_max_score_delta=0.5000 tol_max_noul_delta=0.0500 tol_max_threshold_crossings=0 choice_flips=0 max_probability_delta_observed=0.0200 max_score_delta_observed=0.0000 max_noul_delta_observed=0.0200 threshold_crossings=0 stable_drift=0 boundary_noise=0 within_tolerance=true
```

The fields always appear in this order: `date`, `preset`, `preset_version`,
`cases`, `repeats`, `baseline`, `candidate`, `baseline_models`,
`candidate_models`, `tol_threshold_margin`,
`tol_max_choice_flips`, `tol_max_probability_delta`, `tol_max_score_delta`,
`tol_max_noul_delta`, `tol_max_threshold_crossings`, `choice_flips`,
`max_probability_delta_observed`, `max_score_delta_observed`,
`max_noul_delta_observed`, `threshold_crossings`, `stable_drift`,
`boundary_noise`, then `within_tolerance`. The date, case count, model IDs,
model-count maps, and tolerance values must be real values from the run.
`baseline_models` and `candidate_models` use sorted comma-separated
`served_model:count` pairs, including `unknown` when needed. A line must not
claim a model version that Gateway did not return. `baseline` and `candidate`
show the sole value when a side is uniform and `mixed` when its count map has
more than one value.

### 4.4 exit behavior

- `0`: qualifying cases completed and all configured tolerances passed, with no
  boundary noise.
- `1`: all cases completed, but a flip, delta, or threshold crossing exceeded
  its configured tolerance, including stable drift.
- `2`: missing key, live API error, malformed candidate, incomplete case set,
  boundary noise that prevents a decision, or no qualifying cases. The summary
  still states how many cases completed.
- `64`: invalid command, preset, or tolerance value.

Calibration is intentionally not a gate policy. It is a separate operational
check that can be run before changing a preset version or threshold.

## 5. prefilter

### 5.1 mechanism

The prefilter is an opt-in local BM25-style ranker. It uses only the Python
standard library. It does not add an embedding model, vector store, network
call, tokenizer dependency, stemming, query expansion, or hidden retrieval
model.

The ranker tokenizes the configured query and searchable state text into
lowercase Unicode word tokens. It computes document frequency over all formed
states, then ranks each state with deterministic BM25 parameters `k1=1.2` and
`b=0.75`. Ties use stable `state_ref` order. The searchable text is the focus
and only the context fields named by the preset.

The design follows the TypeSafe re-ranking cookbook: cheap lexical search
creates a shortlist, then Jev judges that shortlist. The prefilter improves
cost and can improve accuracy by removing irrelevant state, because the Jev
jaggedness guidance warns that large irrelevant state degrades judgment.

### 5.2 opt-in and scope

The optional root `prefilter` map has this schema:

```yaml
schema: jm.preset/v2
prefilter:
  ranker: bm25
  top: 100
  query_source: context.query
  fields: [focus, context.file]
```

`ranker` must be `bm25`. `top` must be a positive integer. `query_source`
must be `cli`, `context.query`, `context.predicate`, or `literal`.
`fields` must be a non-empty, duplicate-free list of searchable state-field
names. Each field must occur in the preset question battery's `state_fields`.
`literal` also requires a non-empty `query` string in the prefilter map.
`cli` requires `--prefilter-query`. The two context sources require the
matching invocation input. The ranker uses only these fields, in listed
order, and never searches unlisted state data.

`jm.preset/v1` remains valid when `prefilter` is absent. A preset that has a
`prefilter` map must declare `jm.preset/v2`; the v1 validator rejects that
root field. The v2 validator rejects unknown prefilter fields and all invalid
values before state formation. The schema version is part of the preset
identity and therefore part of cache keys and provenance.

The CLI form is:

```text
--prefilter bm25 --prefilter-top K --prefilter-fields FIELD[,FIELD...]
  [--prefilter-query TEXT]
```

The default is off. A preset may declare the ranker, top, query source, and
fields, but a preset must opt in explicitly. Explicit CLI values override
preset values in this order: `--prefilter` selects the ranker,
`--prefilter-top` replaces `prefilter.top`, `--prefilter-fields` replaces
`prefilter.fields`, and `--prefilter-query` replaces the preset query source
and text. The comma-separated fields option must be non-empty,
duplicate-free, and present in the battery's `state_fields`. If CLI
prefiltering has no preset map, the fields option is required. If a preset map
supplies fields, the CLI option is optional. The final values must still pass
v2 validation. With no CLI override, `jgrep` may use `context.query`,
`jfilter` may use `context.predicate`, and a generic `run` invocation needs a
declared source. `diff-risk-heat` is not prefiltered unless its preset
declares an explicit review query. No command silently invents query terms.

`K` is required and must be positive. It is an absolute maximum number of
states admitted to judgment after ranking. The runner still forms and counts
all input states so coverage remains honest. The prefilter runs after stable
state formation and input validation, before cache lookup and Jev calls.

The v2 CLI supports prefiltering for `run`, `jgrep`, and `jfilter`. `gate`
rejects prefiltering by default because its ordinary contract is fail-closed
on incomplete coverage. A later decision may add an explicit partial-gate
policy, but v2 does not make a filtered gate look complete.

### 5.3 coverage and recall contract

Prefiltered states are skipped states. They count in `coverage_counts.skipped`
and the terminal record has `coverage: partial` with the new
`coverage_reasons` value `prefilter_skip`. The skip-summary error uses the
same stable grouping shape as a scan-cap skip, with boundary
`prefilter=bm25,top=K` and up to eight sample references.

The coverage equation remains:

```text
discovered = judged + skipped
```

`prefilter_skip` is a v2 extension to the closed coverage-reason enum. It is
also added to the skip error kind so a consumer can distinguish deliberate
ranking skips from scan caps and context limits.

`jgrep` writes a stderr warning whenever prefiltering skips a state:

```text
jm: warning: BM25 prefilter skipped 700 of 1000 states; recall is bounded by the shortlist; rerun without --prefilter for full recall
```

An empty result set never implies no match. Consumers must read the terminal
coverage record. A prefilter result is useful for triage, not a proof of
absence.

## 6. self-consistency

### 6.1 supported command and request shape

`--consistency N` is supported by `jm gate` and `jm run`. The short forms
inherit it through `run`. `N` must be at least 2. The recommended starting
value is 15, matching the TypeSafe cookbook.

For each admitted state, the runner sends the resolved question battery N
times. Each call adds a fresh random `uid` field to the state context. The
question instructions must not refer to that field. The uid is throwaway
variation data; it is not emitted as a stable state reference.

The runner uses the first complete response for Choice and Score answers. It
aggregates only Noul answers. This preserves the existing answer shape for
non-Noul questions and avoids pretending that a Choice or Score was tested
for stability.

The aggregate Noul answer keeps the mean as `noul` and adds:

```json
{
  "type": "noul",
  "noul": 0.72,
  "consistency": {"samples": 15, "mean": 0.72, "stddev": 0.01}
}
```

`stddev` is the population standard deviation across the N responses. Raw
samples stay out of normal result JSONL. A future diagnostic flag may expose
them, but v2 does not increase output volume by default.

If the battery has no Noul questions, `--consistency` is a usage error. If any
repeat fails after retries or returns incomplete answers, the state fails and
the gate cannot pass. The runner does not silently reduce N.

### 6.2 gate decision rule

The gate uses the mean for the ordinary threshold comparison only when the
threshold is outside the uncertainty interval. The default interval is:

```text
[mean - 2 * stddev, mean + 2 * stddev]
```

`--consistency-sigma K` changes the multiplier. If a threshold lies inside or
on the interval, the predicate is indeterminate and the gate fails closed with
exit code 2. Otherwise the gate evaluates the mean normally. For example, a
`noul >= 0.75` condition requires the lower interval edge to be greater than
0.75; a `noul < 0.75` condition requires the upper edge to be less than
0.75. Equality is indeterminate.

This rule is deliberately conservative near the threshold. It does not turn
standard deviation into a confidence guarantee. It only prevents an unstable
sample from passing a hard gate.

### 6.3 cache and rate-limit cost

Every uid changes the state and therefore changes the content-addressed cache
key. Each repeat is a distinct cache entry. A normal rerun creates fresh uids,
so it normally performs N live calls again. The cache still makes an exact
replay available if a caller preserves and reuses the exact uid-bearing state.

Consistency is serialized by default. Every repeat uses the shared client
retry policy and honors the Gateway's rate-limit delay, including finite hints
shorter than 60 seconds. No repeat starts after a rate-limit response until
its retry delay completes. A failed repeat makes the invocation operationally
incomplete rather than using fewer samples.

The human summary reports `states * N` attempted calls, cache hits, live calls,
and total normalized token usage. This makes the cost visible before teams
raise N.

## 7. compatibility and schema changes

The v1 commands and v1 record types remain the default when the new options
are absent. v2 requires these additive changes:

- Rename the cache schema to `jm-answer/v2` for new writes. Read v1 entries
  for calibration and one-time cache inspection.
- Keep `jm.preset/v1` for presets without prefiltering. Require
  `jm.preset/v2` for the optional `prefilter` map and include that schema
  version in preset identity, cache keys, and provenance.
- Add `prefilter_skip` to coverage reasons and skip error kinds.
- Allow an optional `consistency` object on Noul answers.
- Permit score legends to preserve structured criteria values when Gateway
  omits a legend.
- Keep `discovered`, `judged`, `emitted`, `skipped`, and `failed` coverage
  counts. Do not add a second count that can contradict them.
- Keep all judgment stdout as JSONL. Calibration has its own JSONL records and
  writes human text only to stderr.

The normalized client response is stable independently of the CLI record
schema. This prevents callers from importing runner records merely to call
Jev.

## 8. non-goals

- Watch mode, streaming mode, and incremental windowing.
- A `--hint` option or query expansion.
- Injection hardening. State is still untrusted data. This remains deferred
  until jm guards real CI.
- Distillation or a local model backend. Distillation stays blocked on Henry's
  TypeSafe Terms of Service check.
- A native TypeSafe API fallback or a second transport.
- Embeddings, a vector database, a hosted search service, or a new heavy
  prefilter dependency.
- Automatic threshold updates. Calibration reports drift; it never edits a
  preset or approves a new threshold.
- A broad policy language, explanations, or model-generated prose.
- A remote or shared cache.
